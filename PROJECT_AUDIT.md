# Аудит проекта ПЛРЛ

Аудит выполнен по архиву `сайт — копия.zip`, загруженному 13.11.2026.

## 1. Видео на главной

`index.html` содержит:
```html
<source src="document_5256077489607847178.mp4" type="video/mp4">
```
Это относительный путь от `index.html`, то есть файл должен находиться в корне проекта рядом с `index.html`, а не внутри `assets/`.

В полученном архиве этого MP4 нет. Также нет `assets/lapta-match.mp4`, хотя этот старый путь указан в исходном README. Поэтому в присланной копии видеоролик отсутствует, а текущая ссылка ведёт на несуществующий файл. Проверка локальных ссылок после очистки выявила только эту отсутствующую ссылку; внутренние CSS/JS/изображения, оставленные в production-копии, существуют. В основной папке пользователя удалять ролик можно только если он больше не нужен на главной; если нужен — оставить файл в корне с указанным именем или изменить `src` на его фактическое расположение.

## 2. Структура и файлы

Оставлены как рабочие:
- `index.html`, `small.html`, `large.html`, `checkout.html`
- `app.js`, `product.js`, `reviews.js`, `landing.js`
- `styles.css`, `gallery.css`, `landing-v2.css`
- `assets/` — используемые сайтом изображения.

Убраны из подготовленной веб-версии:
- `chrome.js`, `header.css`, `header-v2.css` — прежняя собственная шапка/подвал; Tilda предоставляет свои.
- `AGENTS.md` — внутренний файл инструкций, не нужен браузеру.
- `_build_docx.py` — скрипт подготовки документов Word, не относится к сайту.
- `_tmp/` — 50 временных/исходных графических файлов, около 87.46 MiB; ни один из них не подключён страницами сайта.
- пустые `_docx_qa/` и `sources/`.

Это не означает, что оригиналы нужно безвозвратно удалять с компьютера: `_tmp/` и исходники разумно сохранить отдельно как рабочий архив.

## 7. Перед переносом на Tilda

В HTML сохранены относительные ссылки `small.html`, `large.html`, `checkout.html` и `index.html`. После размещения отдельных страниц в Tilda их нужно заменить на реальные URL опубликованных страниц Tilda либо настроить маршрутизацию. Сейчас это локальные ссылки прототипа.

Корзина использует `localStorage`, поэтому она работает в рамках одного origin (домен + протокол). Если страницы окажутся на разных доменах/поддоменах Tilda, данные корзины не будут автоматически общими. Для финального магазина лучше использовать штатную корзину каталога Tilda (ранее обсуждался блок ST100) либо единый origin и отдельную интеграцию.

Форма заказа сейчас не отправляет данные. Для приёма заявок нужно подключить её к Tilda CRM/форме Tilda. Не следует считать локальное уведомление подтверждением реального заказа.
