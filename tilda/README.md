# ПЛРЛ — подготовка страниц товара под Zero Block + Каталог Tilda

**Статус: черновая адаптация исходных макетов. В Tilda не установлено и не протестировано.** Все изменения только в ветке `tilda-store-prep`. Ветка `main` не менялась.

## Архитектура (утверждена)

- Внешний вид страниц: существующий макет из GitHub, [большой формат](large-zero-block.html) и [маленький формат](small-zero-block.html).
- Источник названия, актуальной цены, наличия, количества и оформления покупки: **Каталог товаров Tilda**.
- Для каждой страницы: **ST200** (товар с привязкой по Product ID из каталога). Поддержка такой связки описана официально: https://help-ru.tilda.cc/online-store/one-product
- Общая корзина и оформление: **ST100**. Документация: https://help-ru.tilda.cc/online-store/cart
- Фиксированная доставка: **199 ₽ за один заказ** (не за штуку), средствами ST100.
- **Никакой постоянной иконки в общей шапке/подвале спортивного сайта.** Способ открыть корзину в пределах трёх страниц необходимо проверить в редакторе после установки штатных блоков.
- Платежи и СДЭК **не подключаем**, страницы не публикуем.

## Изменения в визуальных файлах

Удалены самописная корзина `laptaCart`, ссылка `#order:Имя =Цена` с ценой из JS, локальная страница `checkout.html` и отображение цены из `product.js`.
Вместо этого в визуальном блоке размещена ссылка `Выбрать количество и купить` на якорь `#plrl-native-order` — место, куда следует добавить штатный товарный блок ST200. **Сама по себе эта ссылка не добавляет товар в корзину**, что сделано намеренно: покупка и количество должны управляться только Каталогом Tilda.

Визуальные файлы по-прежнему содержат HTML/CSS/JS для галерей и вкладок, без механики покупки. Визуальный блок можно позже разбить на редактируемые элементы Zero Block. **Сейчас это ещё не полноценный Zero Block-макет с отдельными редактируемыми текстами.**

## Настройка одной страницы товара в Tilda

1. Создать черновую страницу большого (или маленького) формата, не публиковать.
2. Создать два товара в Каталоге Tilda, заполнить только подтверждённые данные. В исходном прототипе цены 1299 ₽ и 699 ₽ — предварительные.
3. На соответствующую страницу поставить визуальную часть из `large-zero-block.html` или `small-zero-block.html` в HTML-элемент Zero Block или T123.
4. **Непосредственно под визуальной частью** разместить штатный товарный блок **ST200**. Его визуальный вид и доступные настройки необходимо проверить в реальном редакторе; блок не следует скрывать `display:none`, так как он должен оставаться рабочим, доступным и позволять изменить количество/добавить в корзину.
5. В Каталоге открыть соответствующий товар, скопировать его **Product ID**, а в «Контент» блока ST200 указать этот Product ID — тогда товарный блок использует данные из Каталога.
6. Добавить ST100 «Корзина с формой заказа», настроить ее только в пределах нужных страниц мини-магазина. Если ST100 размещена на нескольких страницах, обязательно проверить единое сохранение покупок.
7. Для фиксированной доставки через форму ST100 настроить способ доставки **`Доставка =199`** (или эквивалентное штатное поле, как предусмотрено в текущем редакторе). Проверить, что итог включает 199 ₽ **ровно один раз** при любом количестве товаров.
8. Настроить невидимый служебный якорь `plrl-native-order` **перед ST200**, чтобы визуальная кнопка прокручивала к штатному товарному блоку. Не ставить элементу `display:none` — браузер не сможет к нему перейти.
9. Переход «Перейти к оформлению» должен быть отдельным штатным способом открыть корзину после её настройки. Не нужно делать это фиктивным кликом по несуществующей иконке.
10. Протестировать открытие корзины, добавление двух товаров, изменение количества, удаление, обновление страницы и фиксированную доставку.

## Что ещё не решено / нельзя заявлять готовым

- Визуальные блоки не тестировались в Tilda. Не подтверждена совместимость CSS `@scope` со всеми целевыми браузерами.
- Не проверены фактические видимые кнопки ST200, их соответствие фирменному дизайну и величина расхождения с исходным макетом.
- Не настроен постоянный способ открыть ST100 через надпись «Перейти к оформлению». Нужно реализовать через работающие штатные элементы без глобальной иконки в header/footer.
- Не внедрены Product ID, отсутствуют подтверждённые текущие цены и остатки.
- Не загружены публичные изображения.
- Нет договоров платежей и СДЭК; оформление, уведомления и отправка заказов не запущены.
- Вкладка «Отзывы» в черновике информационная: реальные отзывы и модерацию предстоит подключить отдельно.

Не публиковать магазин до проверки всех требований.
